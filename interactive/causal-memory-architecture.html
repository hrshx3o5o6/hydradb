HYDRADB — CAUSAL MEMORY ARCHITECTURE

How the system works, how retrieval works, and how each piece wraps around HydraDB.

1. WHAT HYDRADB ACTUALLY IS

SYSTEM LAYER

3. HOW RETRIEVAL WORKS — THE TWO PATHS

RETRIEVAL 
QUERY  "Why did this bug happen?"
  |
  +--- Path A: WHY (graph traversal)
  |
  |    MCP why("bug in auth")
  |         |
  |         +-- search --> find matching Event node(s) by text
  |         |    Cypher: MATCH (n:Event)
  |         |            WHERE n.text CONTAINS 'auth'
  |         |            RETURN n LIMIT 5
  |         |
  |         +-- find_causes(event_id) --> walk CAUSES edges backwards
  |         |    Cypher: MATCH path = (n:Event)-[:CAUSES*1..8]->(a:Event)
  |         |            WHERE n.id = event_id
  |         |            RETURN a, relationship, nodes(path)
  |         |
  |         +-- compose answer from traversal path
  |              "The auth bug was caused by [root cause event]
  |               which led to [intermediate event] which led to
  |               [symptom event]."
  |
  |    Retrieval is structural: walks real stored edges.
  |    No semantic search on retrieval -- the graph IS the structure.
  |    Path = explicit causal chain, not nearest-neighbor embeddings.
  |
  +--- Path B: SEARCH (text match)
  |
       MCP search("database schema")
            |
            +-- Cypher: MATCH (n:Event)
            |           WHERE n.text CONTAINS 'schema'
            |           RETURN n, n.timestamp
            |           ORDER BY n.timestamp DESC LIMIT 10
            |
            +-- Returns nodes, not paths.
            |   Useful as a starting point for why/find_causes.
            |
            +-- Combines with Path A:
                1. search("what changed in memory.py")  -->  find node
                2. find_causes(node_id)                 -->  walk ancestors
                3. Agent reads the chain + composes answer

4. THE WRITE PATH — HOW EDGES GET CREATED

WRITES 
HOW CAUSAL EDGES ENTER THE GRAPH
Two paths, both end with HydraDB MERGE (idempotent, safe re-run).

  +--- Manual (host-reasoned) -------------------------------------------------
  |                                                                              |
  |  1. Agent (or human) reads recent events via search                        |
  |  2. Agent reasons about which events are causally linked                   |
  |  3. Agent calls link(src_id, dst_id, CAUSES, mechanism="because...")       |
  |  4. MCP server writes: MERGE (a)-[r:CAUSES]->(b) SET r.confidence, r.mech  |
  |                                                                              |
  |  Used during: agent-directed memory curation, A/B testing                 |
  +------------------------------------------------------------------------------

  +--- Automatic (edge discovery daemon) -----------------------------------------
  |                                                                              |
  |  1. edge_discovery.py polls HydraDB every 5s for new event count            |
  |  2. When new events arrive:                                                  |
  |     a. Fetch last 30 events (temporal window)                               |
  |     b. Dedup identical-text events (filter noise)                           |
  |     c. Feed window to LLM with causal-discovery prompt                      |
  |     d. LLM returns edges with: source_idx, target_idx, confidence, why     |
  |     e. Post-filter: confidence >= 0.8, reject tool-->tool action chains     |
  |     f. link() --> MERGE each edge into HydraDB                            |
  |  3. If no new events --> idle, zero LLM cost                                |
  |                                                                              |
  |  Runs continuously. Edges appear automatically as sessions proceed.         |
  +------------------------------------------------------------------------------+

WHY MERGE (not CREATE)?
  Re-running discovery over overlapping windows is safe.
  Same (src, dst, type) --> same edge, confidence/mechanism updated.
  No duplicate edges ever.

5. WHAT MAKES THIS DIFFERENT

FLAT CONTEXT (status quo)

  • Agent gets all history as text in a list
  • Oldest events buried under new ones
  • No structure -- everything is "nearby text"
  • Retrieval = nearest-neighbor in embedding space
  • Scaling: linearly growing context window
  • Why = "the embeddings were similar"

CAUSAL MEMORY (what we built)

  • Agent gets structured traversal paths
  • Causal chain: root cause --> intermediate --> symptom
  • Structure = explicit typed, weighted edges
  • Retrieval = walk real edges in the graph
  • Scaling: graph grows, traversal stays bounded (1..8 hops)
  • Why = "here is the chain and why each link exists"

6. THE DATA MODEL AT A GLANCE

SCHEMA 
Node: Event
  id          string    FNV-1a 63-bit hash (dedup-safe)
  text        string    The actual content (what was said/done)
  session_id  string    Which session created it
  type        string    "user" | "action" | "observation"
  topic       string    Optional: topic tag
  timestamp   int64     Unix epoch ms

Edge: CAUSES  (directed, a --> b)
  confidence  float     0.0 - 1.0 (LLM-judged or human-set)
  mechanism   string    Natural-language explanation of why a caused b

Edge: ENABLES / OVERWRITES / CONFLICTS
  (same schema, different semantics -- agent chooses the right type)

7. MARKETING ANGLE

PITCH 
The problem:
  AI agents forget. Context windows are flat lists of text.
  When something goes wrong, you get "the embeddings were similar"
  as an explanation. No root cause. No chain of events.

The solution:
  HydraDB causal memory gives agents a graph of what happened and why.
  Every decision, every tool call, every outcome is a node.
  Every causal link between them is a weighted, typed edge.
  Retrieval = walk the chain. Answer = the actual causal path.

What makes it work:
  1. Self-writing -- plugin records events automatically, zero manual work
  2. Auto-discovery -- daemon finds causal edges as they happen
  3. Structural retrieval -- walks real edges, not similarity search
  4. 3D visualization -- see the entire causal graph in your browser
  5. Provenance -- every edge carries "why" + confidence score

One-liner:
  "Memory that remembers why, not just what."
